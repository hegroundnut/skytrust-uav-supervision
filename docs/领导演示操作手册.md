# 云巡信链 SkyTrust · 领导演示操作手册（四端四链 · 链上见证版）

> **本手册干什么**：按项目原始目标节奏（`docs/demo-script.md`《紧急医疗运输》九章剧情）带领导走一遍全平台。
> 与解说剧本的分工：`demo-script.md` 管「讲什么」（台词+精确表单值）；**本手册管「看什么」**——每一步操作完成后，
> 结果**在区块链浏览器或其他页面的哪个位置当场可见**、这一步**与前面/后面哪一步相扣**。
>
> **核心卖点一句话**：四端共享同一份数据、四种视角；每一次跨链动作都真实写入四条国产/联盟链，
> 任何一步的存证都能在「链上浏览器」里当场回读——**存证不是截图，是实时回读**。
>
> 预计总时长约 35 分钟（纯操作不讲解约 18 分钟）。

### 1.3 开场整备（index.html，约 2 分钟）

1. 打开内部导航页 → SPA「平台总览」→「演示维护」区：点「**灌注演示数据 demo/init**」获得剧情种子（厂商 3 / 运营商 3 / 航空器 7 / 航段 5 / 节点 8）。
   如需从头重演：先点「**复位演示数据 demo/reset**」（红色确认框）再灌注。
2. **红线**：复位只清空业务库，**四条链上已经写入的账本永不受影响**——链上记录不可删，这正是区块链的意义（可向领导如实说明）。
3. 地图底图：首次进地图页若弹「天地图 key」引导，粘贴 key 或点「跳过」（矢量层航线/区域/节点/无人机照常自绘，不影响演示）。
4. 依次打开四个门户标签页（每端先出演示登录页：账号 test / 密码 test；四端登录态互相独立、会话级，关标签页后需重新登录；侧栏底部有「退出登录」），确认各端主题、侧边栏、顶栏 4 盏灯。

### 1.4 三条全局纪律（讲解人遵守）

1. **时间窗一律用表单默认/相对值**（任务窗=当前+1h～+4h；许可窗=当前−1h～+4h），任何钟点演示都不用改。
2. **第 7 章「申报轨迹」参数全程留空**（填了会触发偏航告警、污染驾驶舱统计）。
3. **本演示是真实上链**：每次「提交跨域申请 / 签发 / 吊销 / 授权裁决」都会永久写入真实链账本，跨链动作耗时数秒——**这个"慢"就是真实 BFT 共识的节奏，本身是卖点**（模拟系统才会瞬间返回）。

## 二、节奏总览与证据主线（讲给领导的"故事地图"）

**九章节奏**（与 demo-script 完全一致）：

```
第0章 整备 → 第1章 建档 → 第2章 任务申请 → 第3章 审核与签发 → 第4章 起飞
          → 第5章 攻防 → 第6章 追踪 → 第7章 授权开箱 → 第8章 收尾 → 第9章 链上浏览
```

**四条证据主线**（步骤之间的关联就是这四条线，每章表格的「关联」列回指到这里）：

- **A 航空器存证线**：第1章登记 `UAV-MED-01` → 跨链四段存证（UAV_REGISTER_PROOF）→ 第3章签发守卫要求它恰为 VERIFIED → 第8章状态机收官 ACTIVE。
- **B 证照生命周期线**：第3章证照中心签发 `PASS-2026-001`（源发于 IRITA 证照链）→ 第4章起飞前验证绿灯 → 第6章七级追踪第 L3 级命中它 → 第8章吊销（PASS_REVOKE 上链）→ 复验红灯。**一张证从生到死，每一步都有链上凭证。**
- **C 任务跨域线**：第2章创建任务（描述加密入库、界面只见脱敏值）→ 跨链提交（MISSION_APPLICATION）→ 第3章管理当局裁决回传（MISSION_REVIEW_RESULT）→ 第7章凭授权开箱明文重现 → 第8章审计台账闭环。
- **D 安全监管线**：第5章虫洞攻防（链下可信网络）→ 攻击事件留痕 → 第6章监管告警 `ALERT-2026-001` 与七级追踪 → 第7章授权 `AUTH-2026-001` 上链 → 密文核验 → 第8章监管审计导出。

**四方分权叙事主轴**（贯穿全场的一句话）：申请（运营商）→ 审批（管理当局）→ 签发/吊销（证照中心）→ 验证（运营商/监管）——**审批者不发证，发证者不审批，监管全程可见但开箱需授权**。

## 五、链上浏览器速查（四端末位菜单「链上浏览器」）

**三区同页**：①节点情况（四链总览卡+节点表）②块浏览（最近块→块详情→交易直查）③链上数据追踪（跨链流水按五类报文过滤→四段存证详情→任一段 TxID 直查回读）。

**四端裁剪对照**（同一模块、不同视角——第 9 章压轴用）：

| 端 | 默认视角 |
|---|---|
| 运营商端 | 聚焦与自己相关的报文（任务申请 / 飞行许可） |
| 管理当局端 | 四链全量 |
| 监管当局端 | 全量 + 跨链存证中**监管链中继段高亮**（监管不可旁路） |
| 证照中心端 | 默认深钻 **IRITA 证照链**（链卡/节点/块初始选中 irita） |

**两条诚实红线**（领导问「数据是不是真的」时的标准回答）：
1. 一切块高/TxID/哈希实时来自链上，绝不硬编码；节点表 source 列如实标注数据来源（rpc=链原生实测）。
2. 查不到就显式拒绝（乱造 TxID → 参数校验拒绝），某链不支持的查询如实降级展示——**绝不虚构收据与区块**。

## 六、常见问题（讲解人备答）

| 问题 | 回答 |
|---|---|
| 跨链提交为什么要几秒钟？ | 真实四链 BFT 共识的节奏：证照链出块档 1 秒、监管链 5 组织共识逐跳确认。模拟系统才会瞬间返回——**慢，恰恰是真的**。 |
| IRITA 块高为什么涨这么快？ | 证照链开启空块连续出块（约 1.5 秒/块），账本连续可审计；FISCO 相反——有交易才出块。两种出块策略都如实展示。 |
| demo/reset 会不会销毁链上数据？ | 不会。复位只清业务库；四链账本不可篡改、不可回滚——已上链的存证永远在。 |
| 证件号是真的吗？ | 演示环境只收**模拟证件号**，系统不采集、不存储任何真实证件信息（界面不作标注——产品化观感；被问及时口头说明）。 |
| 明文去哪儿了？ | 任务描述创建时即加密入库，全平台任何角色任何界面只见脱敏值；唯一开箱路径 = 第7章的授权+范围+时间窗三重门。 |
| 为什么审核员不能发证？ | 四方分权设计：审批（管理当局）与签发（证照中心）物理分离在不同门户、不同链上身份——谁也不能一手遮天。 |
