# 云巡信链（SkyTrust）· 验收演示讲解人手册（四链四端 × 三条研制目标）

> **手册定位**：本手册是给**讲解人**用的验收演示 runbook——按三条研制目标分章组织，每步五要素钉死格式，使三条研制目标的演示动线与新版浏览器证据面（布局 E 六段）一一咬合。它不是给验收专家的自助说明书；剧情叙事视角见 `docs/demo-script.md`（四端版，与本手册同源同值、步骤等效，对照见附录 D）。端点与错误码语义一律以 `services/skytrust-backend/README.md`（80 个 POST 端点单一事实源）与 `internal/errcode` 为准。
>
> **数字纪律（全手册红线）**：手册中一切数字/时延**一律不预填**——以**现场屏幕读数**为准，或以**实测为准**（真实链历史实测登记于 `docs/version-matrix.md`）。唯一例外 = 各步「预计耗时」（分钟级计划值）。话术引用链上证据处一律写明「指向屏幕上的 X」（芯片①留痕数 / 时间线节点 / 4 段 TxID / SM 徽章）。真实链数据将在新机器上重跑——任何 TxID/时延/计数都不得从旧文档抄进讲解词。
>
> **生产安全红线**：生产后端 `:8080` 与生产前端代理（`:8090` 或现场部署入口，见 version-matrix §12.10）为**生产实例**——**生产环境严禁 `demo/reset`、严禁杀进程、严禁重启链**；讲解人在生产上只做**界面操作与只读目检**。手册中全部命令行示例**只存在于附录 C 隔离排练环境**（`:18080`/`:18090` + `/tmp` 数据目录），绝不指向生产端口。
>
> **执行顺序**：§0 演前整备 → §1 目标① → §2 目标② → §3 目标③。存在跨章依赖：§2 起飞报备依赖 §1 的任务与许可 `PASS-2026-001`；§3 七级追踪 L3 依赖同一张许可。总时长约 36 分钟（5+15+8+8，不含可选加演）。

- 【操作】假名 PSEUDO-UAV-83921、事件类型 WORMHOLE_ALERT（默认）、风险 HIGH（默认）、来源 SYSTEM2、操作员 REG-01（默认）、告警号显式 ALERT-2026-001、关联任务 = 医疗任务号（芯片预填；首次为空则手填顶栏 MISSION 芯片值）→「登记告警」。
- 【屏幕】告警台账新行 OPEN 徽章（图标+文字）；假名 + 证据 SM3 摘要落库。
- 【解说】监管域只见**匿名假名**——明文身份不出域；本条告警的证据来源就是 §2 的虫洞事件（来源 SYSTEM2），三系统在同一份事实上闭环。
- 【证据】指向台账 OPEN 徽章行 + 告警号芯片自动记录。
- 【故障兜底】6002（枚举/必填守卫）→ B-7。

### 步骤 3.2 · rg 七级跨链身份追踪：全链可溯（高光）（预计耗时约 1.5 分钟）

- 【端】监管当局端「身份追踪」（告警台账行「发起七级追踪 →」直达，或侧边栏「身份追踪」页）。
- 【操作】入口 alert_id 预填 ALERT-2026-001、操作员 REG-01 →「发起七级追踪」。
- 【屏幕】追踪结论卡「全链可溯」（break_level=0）；七级时间线逐级绿灯：L1 假名→身份映射 IDM-DEMO-0001（监管链索引）/ L2 设备地址 / L3 证照 PASS-2026-001（**正是 §1.5 签发的那张**）/ L4 SM9 身份签章验证 / L5 航空器（UAV-A-001，Fabric 明细）/ L6 运营商（Operator-A）/ L7 生产商（Manufacturer-B，FISCO 兜底）；每级耗时与总追踪时延 trace_latency_ms **读现场屏幕**（秒级）。
- 【解说】从匿名假名到实名主体，七级证据链**逐级可溯、无一靠猜**：L1–L4 出自监管链索引、L5–L6 出自运营链明细、L7 出自管理链——跨链索引是证据枢纽，全程秒级完成（指时延读数）。**诚实注记（如实讲）**：种子索引把该假名绑定到平台内置剧情航空器 UAV-A-001，其证照号与医疗许可 PASS-2026-001 同号同源——演示环境共用同一剧情证据链；追踪能力本身与绑定对象无关。
- 【证据】指向七级时间线 + break_level=0 结论卡 + 追踪时延读数（以现场实测为准；real 模式历史实测登记于 version-matrix）。
- 【故障兜底】正例意外断链 5001 → B-10（先如实讲断点，再对照种子注记排查 §1.5 是否显式使用了 PASS-2026-001）。

### 步骤 3.3 · rg 断链红线：宁断链，不拼身份（必演「失败」）（预计耗时约 1 分钟）

- 【端】监管当局端「身份追踪」。
- 【操作】入口切「航空器假名（pseudo）」，填 PSEUDO-UNKNOWN-999 →「发起七级追踪」。
- 【屏幕】5001 错误卡——L1 BROKEN（「chainmaker 索引中无此身份映射」）+ L2–L7 全部「skipped: 断链于第 1 级」（断点时间线证据）。
- 【解说】**系统宁可返回断链，也不拼凑一个假身份**——断点之后没有任何一级是「看起来像」的推断，这就是监管的诚实性；断点证据（哪级断、为什么断、后续为何跳过）本身就是可归档的监管结论。
- 【证据】指向 L1 BROKEN 徽章 + L2–L7 skipped 理由文字（断点证据原文）。
- 【故障兜底】本步即设计内「失败」——若意外返回成功，才是故障（核对假名拼写，必须是索引中不存在的值）。

### 步骤 3.4 · rg 告警线性状态机（预计耗时约 1 分钟）

- 【端】监管当局端「告警管理」·「状态机推进」卡。
- 【操作】单步推进 ALERT-2026-001 四步：IDENTIFIED（已定位假名）→ TRACED（七级追踪完成）→ REVIEWED（人工复核：攻击已隔离）→ RESOLVED（路径已恢复，告警闭环），每步填理由、操作员 REG-01。
- 【屏幕】台账徽章逐步同步（图标+文字），终态 RESOLVED；四步理由全程留痕可回看。
- 【解说】线性状态机只允许单步——跳级推进会被 6002 显式拒绝（可口头讲，不必真点）；每次推进都必须留理由，监管动作本身也被监管。
- 【证据】指向徽章逐步变化 + 推进理由留痕记录。
- 【故障兜底】6002（跳级/状态非法）→ 预期行为，如实讲「守卫在工作」。

### 步骤 3.5 · rg 授权申请 + 审批上链（预计耗时约 1 分钟）

- 【端】监管当局端「授权中心」。
- 【操作】① 「申请授权」：监管方 REG-01（默认）、scope 四项全勾 MISSION+ROUTE+PAYLOAD+IDENTITY（**表单默认只勾 ROUTE+PAYLOAD，需补勾两项**）、目标类型 MISSION（默认）、目标编号 = 医疗任务号（芯片预填）、授权号显式 AUTH-2026-001、理由「虫洞告警排查：需核验医疗任务申报与载荷一致性」、生效/失效保持默认（当前−1 小时至+4 小时相对值）→「提交授权申请」；② 同页「审批」区：授权号芯片预填、裁决 APPROVE（默认）、审批人 REG-ADMIN（默认）、批注「情况属实，同意开箱核验」→「审批」。
- 【屏幕】✓ AUTHORIZED（已上链）+ ChainMaker 监管链存证回显（chain_tx_id 可查）。
- 【解说】授权 = **范围 × 目标 × 时间窗**三元组；审批 APPROVE 会写入监管链监管授权合约——**授权行为本身也是链上存证**（DENY 不上链）；real 模式该 chain_tx_id 为监管链真实交易（以实测为准）。
- 【证据】指向 AUTHORIZED 徽章 + chain_tx_id 回显（可点开链上回执）。
- 【故障兜底】2001（授权上链失败，保持 PENDING 可重试）→ B-11。

### 步骤 3.6 · rg 密文核验：未授权只见封缄（必演「失败」）（预计耗时约 1 分钟）

- 【端】监管当局端「密文核验」。
- 【操作】**先清空授权**：顶栏 AUTHORIZATION 芯片点 ✕ 清空（或授权号输入框显式清空）；任务编号保持医疗任务号；「申报载荷类型」「申报轨迹」均留空（全局纪律）→「执行核验」。
- 【屏幕】5002 封缄拒绝——只回封缄元数据：ciphertext_status「SEALED」/ sm3_hash 摘要 / masked_value 掩码值 / has_ciphertext；**响应中没有任何明文字段**；监管审计台账同步落一条未授权核验留痕（事件类型以屏幕为准）。
- 【解说】未授权不开箱——数据最小化：即便是监管方自己，未持有效授权也只能看到「有密文、摘要如此、掩码如此」这一层事实；**明文永不进错误信封**；未授权尝试同样被审计留痕，监管者也被监管。
- 【证据】指向封缄卡三元（状态/摘要/掩码值）+ 监管审计台账新行。
- 【故障兜底】本步即设计内「失败」——若意外开箱成功，才是故障（核对授权确已清空）。

### 步骤 3.7 · rg 授权开箱：密文可控不可见（隐私闭环高光）（预计耗时约 1 分钟）

- 【端】监管当局端「密文核验」。
- 【操作】授权号重填 AUTH-2026-001（芯片自动回填）、任务编号 = 医疗任务号、申报载荷类型 MEDICAL_KIT、「申报轨迹」**留空** →「执行核验」。
- 【屏幕】✓ 开箱成功——任务描述**明文回显**（§1.3 起全程掩码的「特殊血液样本（RH 阴性）…」原文重现）+ 授权校验 ✓ + scope 四项回显 + 完整性双验证 ✓✓ 双通过（SM3 摘要一致 + SM9 签名有效）+ 载荷一致性结论（PAYLOAD_OK 等结论字段以现场为准）+ 核验上链存证（chain_tx_id）。
- 【解说】开箱必须同时满足**有效授权 + 范围命中 + 时间窗内**三条件；明文可见只对这一次授权、这一个范围、这一个窗口负责，解密视图即看即走不落库。§1 处处掩码、此处凭授权开箱——**密文可控不可见**，隐私与监管在同一份密文上同时成立。
- 【证据】指向 ✓✓ 双通过徽章 + 明文回显 + 载荷一致性结论 + chain_tx_id 上链存证。
- 【故障兜底】5003（范围缺项）/ 5004（窗口外）→ 如实讲缺哪个条件（对照 3.5 的 scope 四项与相对时间窗）。

### 步骤 3.8 · 目标③收口：芯片③活数 + 监管端中继段高亮（预计耗时约 0.5 分钟）

- 【端】监管当局端「链上浏览器」（#/chainview）。
- 【操作】指向芯片③；随手点击时间线任一节点开四段存证抽屉。
- 【屏幕】芯片③「告警 N · 身份追踪 N / 密文核验 N · 授权 N」（活数——§3 各步刚刚各 +1）+ 跳转「身份追踪 →」；rg 端抽屉内**监管链中继段高亮**（.d-cxv-reg-hl + 「② 监管链签收 / ③ 监管链中继」文字标注，图标+文字非仅颜色）。
- 【解说】目标③的秒级追踪与密文监管，计数就是刚才现场产生的活数；监管端浏览器对监管链段的专属高亮 = 监管链非旁路语义的直观呈现。
- 【证据】指向芯片③四个读数（以现场实测为准）+ 高亮中继段。
- 【故障兜底】芯片错误态 → B-1。

## 附录 B · 故障恢复（讲解人现场处置）

## 附录 C · 隔离排练环境（:18080 sim，绝不接触生产）

> **用途**：验收前在隔离模拟环境把本手册 §0-§3 全流程走一遍（含附录 A 剧情值），核对每步五要素的【屏幕】预期回显。
> **硬红线**：隔离环境 = `:18080`（后端）/ `:18090`（前端代理）+ `/tmp` 数据目录；**绝不接触生产 `:8080`/`:8090`（或现场部署入口）**——不发请求、不碰进程；`demo/reset` 只允许出现在本附录环境。以下命令行示例全部只指向隔离端口。

### C.1 启动（模式与 verify-three-portals-story.sh 同源）

```bash
# 环境（部署机 Go 在 /usr/local/go）
source scripts/env.sh    # 或最小化：export PATH=/usr/local/go/bin:$PATH && export GOPROXY=https://goproxy.cn,direct

SIM_DIR=/tmp/skytrust-manual-rehearsal-$$
mkdir -p "$SIM_DIR"

# 隔离 sim 后端（:18080，DB 与 SM9 密钥全在 /tmp）
cd services/skytrust-backend && go build -o "$SIM_DIR/skytrust-sim" ./cmd/server && cd ../..
SERVER_ADDR=":18080" DB_PATH="$SIM_DIR/sim.db" SM9_KEY_DIR="$SIM_DIR/sm9" CHAIN_MODE=sim \
  OFFCHAIN_AUTOPILOT_MS=2000 TELEMETRY_AUTOPILOT_MS=2000 \
  "$SIM_DIR/skytrust-sim" >"$SIM_DIR/backend.log" 2>&1 &
BACK_PID=$!

# 前端代理（:18090 → 只指向隔离后端）
PORT=18090 BACKEND=http://127.0.0.1:18080 python3 scripts/serve-frontend.py >"$SIM_DIR/frontend.log" 2>&1 &
FRONT_PID=$!
```

等 `backend.log` 出现监听就绪后探活（**只允许打 :18080**）：

```bash

```
