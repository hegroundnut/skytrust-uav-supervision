### 0.2 环境形态（真实链模式——与仿真排练的本质区别）

本演示实例为**真实三链部署**（`CHAIN_MODE=real`）：

| 链 | 角色 | 实例 |
|---|---|---|
| ChainMaker（长安链） | 监管链——跨链必经中转，非旁路 | 真实节点 :12301 |
| Hyperledger Fabric | 运营链——运营方业务 | 真实节点 :7051 |
| FISCO BCOS | 管理链——管理方职能 | 真实节点 :20200 |

- **每一次跨链动作都真实上链**：四段 TxID（`source_chain_tx_id` → `reg_receive_tx_id` → `reg_relay_tx_id` → `target_chain_tx_id`）逐段落链，可在回执抽屉逐段核对，亦可经链上浏览器回查。跨链时延为真实链实测（秒级量级），回执内分段时延可查（crosschain/query）。
- **链下网络（系统二）为链下引擎**：消息时延基线（≈40ms 心跳 / 虫洞骤降 ≈19ms）与链模式无关，两模式一致。
- **`demo/reset` 红线（P6-R6）**：只清空本地业务表（20 张）并复位模拟链状态，**真实三链账本永不受影响**；已上链的 TxID 记录留在链上。
- API 层排练用 `scripts/verify-three-portals-story.sh`（隔离仿真环境 :18080/:18090，182 断言，绝不触碰生产实例）；浏览器层按本文档人工执行。

### 0.4 全局交互约定（读懂每一步回执的前提）

| 约定 | 内容 |
|---|---|
| **API 铁律** | 所有端点一律 POST；HTTP 状态码恒 200，**业务成败看响应体 `code`**（0=成功，非 0=错误码）。统一信封 `{code, message, data, trace_id, timestamp}`。 |
| **verify 铁律** | `pass/verify`、`sm9/verify` 等核验类端点对存在的对象**永远 code=0**——业务结论在 `valid`/`reasons` 字段。「验证动作成功」≠「数据可信」，红灯（valid=false）不是故障，是系统在诚实说话。 |
| **错误呈现** | 三端页面以**错误卡 + 解说词典**（explain.js）呈现设计内拒绝，无「◈ 预期」徽章（那是 index.html 旧一键实跑剧本的标记）。 |
| **时间纪律** | 时间输入一律**相对指令**（如「当前时间 −1 小时」），全文档零固定钟点——无论几点演示都不用改数据。 |
| **轨迹纪律** | 系统三密文核验的「申报轨迹」参数**全程留空**（填 NORMAL 会撞硬编码基线必报偏航、污染驾驶舱统计——红线）。 |
| **证件号红线** | 演示环境仅收取**模拟证件号**（格式示意统一社会信用代码/身份证号），系统不采集、不存储任何真实证件信息。 |
| **坐标红线** | 走廊坐标来自**真实底图鼠标点选**，系统从不造假坐标；lat/lon 双零 = 未设 → 地图不画不连不猜。 |

## S1 · 系统一：任务申请跨域协同（约 12 分钟）

## S2 · 系统二：链下可信网络（约 7 分钟）

**跨端叙事**：管理端是全量视角（攻击节点一直看得见）；运营商端**从不显示** ATTACKER 节点——**信息边界即角色边界**。攻击→检出处置→恢复全程两端同步可见。

### S2-6 诱入消息：「太快」就是破绽（管理当局端）

- **浏览器位置**：`authority.html#/netsec`「会话·消息」页签
- **操作与示例数据**：向医疗会话发诱入消息——会话号 chip 预填、消息类型 `POSITION_UPDATE`、**源节点改为 `UAV-MED-01-NODE`**（表单默认是 UAV-A-001-NODE，必须改）、目标节点 `MGR` → 「发送」。

### S2-8 攻击影响的跨端可视化（运营商端）

### S2-9 路径重算恢复（管理当局端 → 运营商端）

- **浏览器位置**：`authority.html#/netsec`「攻防演练」→「会话·消息」→ `operator.html#/ops`

- **⛔ 设计内失败（守卫说明）**：对健康（非 DEGRADED）会话点「切换路径」→ **4002**（无意义操作必须拒绝）。

- **⛔ 设计内失败 #4（必演）**：向已关闭会话再发消息 → **4002 会话守卫**。台词：关闭的会话不许再说话——会话状态机与消息引擎强一致。

## S3 · 系统三：跨域可信监管（约 10 分钟）

**结束语**：一次紧急医疗运输，三个浏览器标签页，三个系统目标——运营商端得到**便利**（即申即发、一键报备、飞行可见），管理端得到**裁决权**（脱敏审核、许可签发、链网安全运营），监管端得到**证据链**（告警、追踪、授权开箱、审计）。三端共享同一份数据、三种视角——**便利从不绕过监管，监管从不阻碍合规**。而附录 B 里的每一次「拒绝」，恰恰都是系统在保护你的时刻。
